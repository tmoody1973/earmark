# Earmark integration research (2026-10-16)

Convention: each fact has a source. "NOT DOCUMENTED" = not found in the sources read. Apple doc URLs below are the human pages; content was read from Apple's JSON doc feed `https://developer.apple.com/tutorials/data/documentation/applemusicapi/<slug>.json` (the HTML pages are JS-rendered and WebFetch returns nothing).

## 1. Apple Music API / MusicKit JS v3

### Developer token
- Algorithm ES256 only; other algs or unsigned = 401. Header: `alg` = `ES256`, `kid` = 10-char MusicKit key ID. Claims: `iss` = 10-char Team ID, `iat` (unix seconds), `exp` (unix seconds). Optional `origin` claim: array of allowed origins (recommended for web clients). Source: https://developer.apple.com/documentation/applemusicapi/generating-developer-tokens
- Max expiry: `exp` must not exceed 15777000 s (6 months) from current server time. Same source.
- Sign with the MusicKit `.p8` private key (created as a "Media Identifier and private key": https://developer.apple.com/help/account/configure-app-capabilities/create-a-media-identifier-and-private-key/). Send as `Authorization: Bearer <token>`. Source: generating-developer-tokens page above and user-authentication page.
- Implementation note (not from Apple): `jose` `SignJWT` with `importPKCS8` handles ES256; mint server-side, never ship the .p8.

### Catalog search
- `GET https://api.music.apple.com/v1/catalog/{storefront}/search?types=songs,albums,artists&term=beach+bunny` (spaces as `+`; params `l`, `limit`, `offset`, `types`, `with`). Source: https://developer.apple.com/documentation/applemusicapi/search-for-catalog-resources-(by-type)
- Response: `results.{artists|albums|songs}.data[]`, each `{id, type, href, attributes}`. Artist sample attributes: `name`, `genreNames`, `artwork`, `url`. Source: same page.
- `artwork`: `{width, height, url, bgColor, textColor1-4}`. `url` is a TEMPLATE containing `{w}x{h}` (e.g. `.../{w}x{h}bb.jpg`); substitute integers before use. Source: https://developer.apple.com/documentation/applemusicapi/artwork
- Album attributes: `artistName`, `artwork`, `name`, `releaseDate` (YYYY-MM-DD or YYYY), `trackCount`, `upc`, `url` (Apple Music share link), `genreNames`, `recordLabel`, `isSingle`, `isComplete`, `contentRating`, `playParams`. Source: https://developer.apple.com/documentation/applemusicapi/albums/attributes-data.dictionary
- Song attributes (`url`, `artwork`, `albumName`, `isrc`, etc.): not read; verify at https://developer.apple.com/documentation/applemusicapi/songs. NOT VERIFIED.

### Library playlists
- Create: `POST https://api.music.apple.com/v1/me/library/playlists`, body `{attributes:{name, description, isPublic}, relationships:{tracks:{data:[{id,type}]}, parent:{...}}}`. Success 201 with `data[0]` (`type: library-playlists`, id like `p.RB1AAkGsv74Zkl`). Needs Music-User-Token. "There may be a delay before a new resource appears in a user's library." Source: https://developer.apple.com/documentation/applemusicapi/create-a-new-library-playlist
- Add tracks: `POST /v1/me/library/playlists/{id}/tracks`, body `{data:[{id,type}]}`, success 204 no body. Source: https://developer.apple.com/documentation/applemusicapi/add-tracks-to-a-library-playlist
- **Allowed track `type` values: `library-music-videos`, `library-songs`, `music-videos`, `songs`. NO `albums`.** So an album cannot be added to a playlist as one item; you must fetch the album's tracks (`GET /v1/catalog/{sf}/albums/{id}/tracks` or `?include=tracks`) and add each song id. Source: https://developer.apple.com/tutorials/data/documentation/applemusicapi/libraryplaylisttracksrequest/data-data.dictionary.json
- Add whole album to the user's LIBRARY (not a playlist): `POST /v1/me/library?ids[albums]=1577502911` (also other types via `ids[...]`). Returns 202 Accepted, no body; unaddable IDs are silently ignored; may not have completed. Source: https://developer.apple.com/documentation/applemusicapi/add-a-resource-to-a-library
- Two Earmark paths: (a) album card = "add to library" (202) ; (b) playlist = expand to song ids first.

### Music-User-Token
- Header `Music-User-Token: <token>` alongside `Authorization: Bearer <dev token>` on any user-specific request. Source: https://developer.apple.com/documentation/applemusicapi/user-authentication-for-musickit
- Lifetime: NOT DOCUMENTED by Apple. Forum reports: Apple staff say ~6 months and not configurable; other devs report 403s after 1-2 days; no refresh mechanism (handle 401/403 by re-running authorize). Sources: https://developer.apple.com/forums/thread/724576, https://developer.apple.com/forums/thread/654814, https://developer.apple.com/forums/thread/744156 (secondary, via search snippets, not read in full).

### MusicKit JS v3 (web)
- Script: `<script src="https://js-cdn.music.apple.com/musickit/v3/musickit.js" async></script>` (HTTP 200 verified). Source: https://js-cdn.music.apple.com/musickit/v3/docs/iframe.html?id=get-started--page&viewMode=story
- Wait for the `musickitloaded` event, then `await MusicKit.configure({ developerToken, app: { name, build?, icon? } })` (name required; also optional `bitrate`, `storefrontId`). Returns Promise<MusicKitInstance>; `MusicKit.getInstance()` afterward. Source: https://js-cdn.music.apple.com/musickit/v3/docs?path=%2Fstory%2Fget-started--page
- `music.authorize()`: `Promise<String | void>`; opens sign-in flow; resolves immediately if user already authorized and MUT valid; resolved value is "a string representing the user", `undefined` if cancelled. `music.isAuthorized` boolean. Source: https://js-cdn.music.apple.com/musickit/v3/docs/iframe.html?id=reference-javascript-musickit-instance--page
- The property name holding the token string (`music.musicUserToken`) was NOT confirmed in fetched docs (ctx7 returned nothing for it). Widely used in practice but treat as NOT DOCUMENTED here; verify in console before building. Apple says MusicKit JS "automatically decorates requests" made via `music.api.music(...)`, so you may not need the raw token at all if API calls run client-side. Source: user-authentication page above.
- Gotcha: raw token must reach your server (POST from browser) if playlist creation runs server-side.

## 2. Notion API (internal integration)
- Current version header: `Notion-Version: 2026-03-11`. Source: https://developers.notion.com/reference/versioning
- 2026-03-11 breaking changes vs 2025-09-03: `after` in append-children replaced by `position`; `archived` -> `in_trash`; `transcription` block -> `meeting_notes`. Source: https://developers.notion.com/docs/upgrade-guide-2026-03-11
- **Data sources model (since 2025-09-03):** create DB = `POST https://api.notion.com/v1/databases` with `parent:{type:"page_id",page_id}`, `title`, `initial_data_source:{properties:{...}}`; response has `data_sources[]` (use that id later). Sources: https://developers.notion.com/reference/database-create , https://developers.notion.com/docs/upgrade-guide-2025-09-03
- Query moved: `POST /v1/data_sources/{data_source_id}/query` (docs text says PATCH for the old path in the upgrade guide; the current reference says POST). Pages created with parent `{type:"data_source_id", data_source_id}`. Sources: https://developers.notion.com/reference/query-a-data-source , https://developers.notion.com/reference/post-page
- Property schemas (create): `{"Genre":{"select":{"options":[{"name":"x"}]}}}`, `{"Date":{"date":{}}}`, `{"N":{"number":{"format":"number"}}}`, `{"U":{"url":{}}}`, `{"Done":{"checkbox":{}}}`, `{"Art":{"files":{}}}`, `{"Name":{"title":{}}}`. Source: https://developers.notion.com/reference/property-schema-object (schema JSON shown in response shape; the create-request form is confirmed by the database-create example).
- Property values (write): files accept `{name, type:"external", external:{url}}` or `{type:"file_upload", file_upload:{id}}`; files write REPLACES the whole list; relation write replaces whole array; select by name (auto-creates option); date `{start:"2026-09-15"}`; number; url; checkbox. Source: https://developers.notion.com/reference/property-value-object
- Relations: response includes both `database_id` and `data_source_id`; requests can no longer give a `database_id` (use `data_source_id`). Two-way = `type:"dual_property"` with `dual_property:{}` in the request (docs show `synced_property_name`/`synced_property_id` in the response). NOTE: the dual_property create example in the doc is a sketch, not a verbatim doc example. Source: https://developers.notion.com/reference/property-schema-object
- Polling by last edit: body `{"filter":{"timestamp":"last_edited_time","last_edited_time":{"after":"<date>"}},"sorts":[{"timestamp":"last_edited_time","direction":"descending"}]}`; supports `after`, `on_or_after`. Doc examples show date-only (`2025-01-01`); whether a full ISO timestamp is honored to the minute is NOT DOCUMENTED on that page. Pagination: `start_cursor`, `next_cursor`, `has_more`; queries cap at 10,000 results; `filter_properties` query param trims payload. Source: https://developers.notion.com/reference/query-a-data-source
- Rate limits: 600 req/min/connection (~10/s) on Business/Enterprise, 180/min (~3/s) otherwise, plus a workspace-wide shared limit; 429 `rate_limited` with `Retry-After` (integer seconds); also handle 529. Limits: rich text 2,000 chars; blocks/rich-text arrays 100; relation 100; payload 1,000 blocks / 500 KB. Source: https://developers.notion.com/reference/request-limits
- For internal connections a page or data source parent is required (can't create at workspace root); the integration must be shared to the parent page. Source: post-page reference above (first half); share step itself NOT read.
- SDK: `@notionhq/client` latest 5.27.0 (npm view). Not checked whether it defaults to 2026-03-11.

## 3. Clerk + Next.js App Router
- `@clerk/nextjs` 7.9.16 (npm view); peer next `^15.2.8 ... ^16.0.10 || ^16.1.0-0`; latest `next` 16.4.2 (npm view).
- File: **`proxy.ts` on Next.js 16+, `middleware.ts` on 15 and below**, contents identical, at project root or `src/`. Source: https://clerk.com/docs/reference/nextjs/clerk-middleware , https://clerk.com/docs/nextjs/getting-started/quickstart.md
- Code: `import { clerkMiddleware } from '@clerk/nextjs/server'; export default clerkMiddleware()` plus matcher config (skip `_next` and static files; always run for `/(api|trpc)(.*)` and `/__clerk/(.*)`). Same source. Note `clerkMiddleware()` does NOT protect routes by default; add `auth.protect()` / `createRouteMatcher` yourself (not shown in the pages I read; NOT VERIFIED here).
- Env vars: `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` (never expose secret). Source: quickstart.md above.
- Single-user restriction options: (1) Dashboard Allowlist: Access mode page > "Enable allowlist" > add identifiers; ONLY in Open mode; case-insensitive; empty allowlist blocks all sign-ups; applies to sign-ups (older apps may apply to sign-ins). **Requires a paid plan in production; free in development.** (2) Restricted / "Invite-only" mode (API value `restricted`): only invited/manual users; plan requirement for this mode NOT DOCUMENTED. Source: https://clerk.com/docs/guides/secure/restricting-access
- Cheapest robust option (my recommendation, not from docs): in proxy.ts after `auth()` compare `sessionClaims.email`/userId to env `ALLOWED_USER_ID` and 403 otherwise; don't rely on Clerk plan.

## 4. Neon + pgvector
- `CREATE EXTENSION IF NOT EXISTS vector;` / column `embedding VECTOR(n)` / `CREATE INDEX ON items USING hnsw (embedding vector_cosine_ops);` / cosine distance operator `<=>` (similarity = `1 - (a <=> b)`); `SET hnsw.ef_search = 100;` (default 40); HNSW dimension limit: `vector` up to 2,000, `halfvec` up to 4,000. Source: https://neon.com/docs/extensions/pgvector
- Driver: `@neondatabase/serverless` 1.2.0. `neon(DATABASE_URL)` HTTP tagged-template = fastest for single queries / non-interactive transactions; use `Pool`/`Client` (WebSockets) only for interactive transactions, sessions or `pg` compatibility. Source: https://neon.com/docs/serverless/serverless-driver
- Recommendation: `neon()` HTTP driver, no ORM. The docs do not discuss Vercel Fluid compute (NOT DOCUMENTED); plain `pg` also works on Vercel functions but was not evaluated here. Passing vectors: send as a string literal `'[0.1,0.2,...]'` with `::vector` cast (practical pattern; NOT in the pages read).
- Migrations: lightest = numbered plain `.sql` files (`db/migrations/001_init.sql`) applied by a ~15-line script using `neon()`/`pg`, tracked in a `_migrations` table. drizzle-orm (0.45.4) adds a schema layer, codegen, and vector-column quirks; skip for a hackathon. (Recommendation, not sourced.)
- Neon MCP tools are available in this environment (`run_sql`, `prepare_database_migration`) for quick setup.

## 5. Slack approval message (only if eve's Slack channel doesn't cover it)
- eve: the locally installed eve skill (`~/.claude/plugins/cache/.../skills/eve/SKILL.md` and `upstream/SKILL.md`) mentions Slack channels but contains NO text on approval buttons or Block Kit. Whether eve's Slack channel does approve/edit/dismiss: NOT DOCUMENTED locally. Check eve docs first.
- Button: `{"type":"button","text":{"type":"plain_text","text":"Approve"},"action_id":"approve","value":"<id>","style":"primary"}` inside a `section.accessory` or `actions` block. `style`: `primary` | `danger` (one primary per set). `value` max 2000 chars; `action_id` max 255 chars, unique within block. Source: https://docs.slack.dev/reference/block-kit/block-elements/button-element , https://docs.slack.dev/block-kit/
- Message limit 50 blocks; set top-level `text` fallback. Same source.
- Interactivity: enable in app settings "Interactivity & Shortcuts", set Request URL. Slack POSTs `application/x-www-form-urlencoded` with a `payload` field (JSON string); `type: block_actions`. Must return HTTP 200 within 3 s. `trigger_id` valid 3 s, single use (for a modal "Edit" via views.open; method name not named on page). Source: https://docs.slack.dev/interactivity/handling-user-interaction
- Verification: raw body; reject if `X-Slack-Request-Timestamp` is >5 min off; base string `v0:{timestamp}:{rawBody}`; HMAC-SHA256 with Signing Secret; hex, prefix `v0=`; constant-time compare to `X-Slack-Signature`. Source: https://docs.slack.dev/authentication/verifying-requests-from-slack
- In Next.js route handler: read `await req.text()` BEFORE parsing, then `new URLSearchParams(body).get('payload')`.
- `block_actions` field names (`actions[0].action_id`, `.value`, `response_url`): not documented on the pages read (they link to a separate payload reference). NOT VERIFIED.

## 6. Amazon Polly generative + Vercel Blob
- `SynthesizeSpeech`: `Engine: "generative"` (enum standard|neural|long-form|generative), `OutputFormat` (mp3, ogg_vorbis, ogg_opus, pcm...), `Text`, `TextType` (text|ssml), `VoiceId`, `SampleRate`. Limit: 6000 chars total, max 3000 billed (SSML tags not billed). Longer: `StartSpeechSynthesisTask` (200,000 total / 100,000 billed, writes to S3). Source: https://docs.aws.amazon.com/polly/latest/dg/API_SynthesizeSpeech.html
- Generative English voices: en-US Danielle, Joanna, Matthew, Ruth, Salli, Stephen, Tiffany; en-GB Amy, Brian; en-AU Olivia; en-IN Kajal; en-IE Niamh; en-NZ Aria; en-SG Jasmine; en-ZA Ayanda. Default sample rate 24 kHz. No speech marks for generative; no newscaster style. Source: https://docs.aws.amazon.com/polly/latest/dg/generative-voices.html
- Regions: us-east-1, us-west-2, eu-central-1, eu-west-2, ca-central-1, eu-central-2, ap-northeast-1/2, ap-southeast-1/2. London/Canada/Zurich support a reduced voice list (Joanna, Ruth, Salli, Stephen, Tiffany, Amy, Brian, Olivia, etc.; Danielle, Matthew not in that list). Use us-east-1. Same source.
- SDK v3: `import { PollyClient, SynthesizeSpeechCommand } from "@aws-sdk/client-polly"` (package 3.1152.0 per npm view). Response `AudioStream` is a stream; in Node use `await res.AudioStream.transformToByteArray()`. The import names and transformToByteArray are standard SDK v3 usage, NOT quoted from a page I read (a skill `aws-sdk-js-v3-usage` exists locally).
- Vercel Blob: `put(pathname, body, options)`; body: ReadableStream | string | ArrayBuffer | Blob. `options.access` REQUIRED (`'private'|'public'`) and must match the store's access setting. Optional: `addRandomSuffix` (default false; recommended), `allowOverwrite` (default false, throws on same pathname), `contentType` (inferred from extension), `cacheControlMaxAge`, `multipart`, `token`. Returns `{pathname, contentType, contentDisposition, url, downloadUrl, etag}`. Auth: OIDC on Vercel by default, else `BLOB_READ_WRITE_TOKEN`. `@vercel/blob` 2.8.2. Source: https://vercel.com/docs/vercel-blob/using-blob-sdk
- Private store URLs are not publicly fetchable (`.private.blob.vercel-storage.com`): an `<audio src>` needs public store or a proxy route. Source: same page.

## 9. Friction-log candidates (things that cost time or surprised during this research and will during build)
1. Apple Music docs are a JS app; WebFetch returns only the title. Workaround: the `tutorials/data/documentation/applemusicapi/<kebab-slug>.json` feed. (Also: WebFetch's summarizer fabricated plausible Apple details from memory when it got no content; trust only the JSON feed.)
2. Playlists accept songs only, not albums; the "save this album" UX needs a track-expansion step or the 202 add-to-library endpoint.
3. Music User Token lifetime is undocumented; forum reports range from 1-2 days to ~6 months; no refresh endpoint.
4. MusicKit JS v3 docs live in a Storybook iframe; the `musicUserToken` accessor was not found in indexed docs.
5. Notion data-sources change: most blog posts/older SDK examples use `/databases/{id}/query` and `database_id` parents, which are now wrong; create returns a separate `data_sources[]` id.
6. Notion files property write replaces the whole list; relation write replaces the whole array.
7. Notion `last_edited_time` filter docs show date-only examples; polling with a high-water mark may need client-side dedupe by `last_edited_time` + page id.
8. Next.js 16 renamed `middleware.ts` to `proxy.ts`; Clerk's own docs track this. Easy to create the wrong file.
9. Clerk Allowlist is a paid feature in production; an allowlist in dev does not prove it works in prod.
10. Vercel Blob `access` must be passed AND match the store setting; private blobs can't be used directly as `<audio src>`.
11. Polly generative: 3000 billed chars per call, no speech marks, region-limited voice list (stay in us-east-1).
12. Slack: 3-second ack, raw-body signature check, form-encoded `payload` JSON; easy to break by parsing the body before verifying.
13. Podcast Index auth needs a per-request SHA-1 header with a 3-minute clock window; MusicBrainz needs a custom User-Agent or gets throttled; Google Places errors without a field mask.
14. Local impeccable plugin (4.0.4) is behind npm (4.6.0).
